Playwright with Java: From Zero to Real Tests

You already know Java. This guide teaches only what is new: Playwright words, objects and methods, and how to use them to test a real web page. Every code example is Java and was run successfully.

Important

Red boxes and rows: learn these first. They are used in almost every test and asked in almost every interview.

Good to know

Blue boxes and rows: useful, but you can learn them later or only when needed.

1. What is Playwright and how does it work?

Playwright is a Java library, made by Microsoft, that controls a real browser (Chromium, Firefox or WebKit). Your Java code says "open this page", "fill this box", "click that button". Then your code checks the result.

Compared with Selenium, Playwright waits automatically before every action, so you write far fewer waits. It also has built-in screenshots, video, tracing and network control.

Your Java test→Playwright library→Playwright driver (Node, hidden inside the jar)→Browser

You never see the middle part. When you run your Java code, Playwright starts it by itself.

The five objects you must understand

ImportantObject hierarchy

ObjectWhat it isReal life picture
PlaywrightThe starting point. Created once.The power switch
BrowserOne browser program (Chrome).The browser application
BrowserContextA clean, isolated browser profile with its own cookies and storage.One incognito window

The chain is: Playwright → Browser → BrowserContext → Page → Locator. The best habit is one new context per test. It is very cheap and every test starts clean, with no cookies left from the last test.

2. Setup in Java (Maven)

ImportantDependencies

Add this to the dependencies of your pom.xml, plus TestNG for running tests.

<dependency>
  <groupId>com.microsoft.playwright</groupId>
  <artifactId>playwright</artifactId>
  <version>1.49.0</version>
</dependency>
<dependency>
  <groupId>org.testng</groupId>
  <artifactId>testng</artifactId>
  <version>7.10.2</version>
</dependency>

What it does: One dependency is enough for Playwright. You can use a newer version from Maven Central.

The first time you run Playwright, it downloads its own browsers (a few hundred MB). To use the Chrome already on your computer, add .setChannel("chrome") when launching, as the examples below do. To download the browsers by hand:

mvn exec:java -e -D exec.mainClass=com.microsoft.playwright.CLI -D exec.args="install"

What it does: Installs Chromium, Firefox and WebKit for Playwright.

Your first test (complete)

import com.microsoft.playwright.*;

public class FirstTest {
    public static void main(String[] args) {
        try (Playwright playwright = Playwright.create()) {                  // 1. start Playwright
            Browser browser = playwright.chromium().launch(
                    new BrowserType.LaunchOptions().setHeadless(false));     // 2. open Chromium with a window
            Page page = browser.newPage();                                   // 3. open a new tab
            page.navigate("https://example.com");                            // 4. go to a page
            System.out.println(page.title());                                // 5. read the title
            page.locator("a").click();                                       // 6. find a link and click it
            browser.close();                                                 // 7. close the browser
        }
    }
}

What it does: The same five steps as in any browser test: open, navigate, act, check, close. The try (...) block closes Playwright for you at the end.

ImportantCross-browser in one line

playwright.chromium() can also be firefox() or webkit(). The rest of the code stays the same. That is how you test on three browser engines.

4. Locators: how to find an element

A Locator describes an element. It is lazy: nothing is searched until you act on it, and it searches again on every action. So it never becomes "stale" like a Selenium element can.

ImportantBest order of choice

Playwright prefers locators that match how a user sees the page: by role (button, link, textbox), by label, by text. These survive HTML changes better than ids and XPath. Use CSS or XPath when there is no better choice.

MethodWhat it doesExample
Importantpage.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Login"))Finds by role and its visible name. Best for buttons, links, headings, checkboxes.
Importantpage.getByLabel("Email")Finds an input by its <label> text. Best for forms.
Importantpage.getByPlaceholder("Search products")Finds an input by its placeholder.
Importantpage.getByText("Welcome")Finds by visible text (partial, ignores case by default). Add setExact(true) for exact match.
Importantpage.locator("#email")CSS selector (or XPath: page.locator("//input[@id='email']")).
Importantpage.getByTestId("submit")Finds by the data-testid attribute. Developers add this just for testing. Most stable.
Good to knowpage.getByAltText("Logo") / getByTitle("Close")Find an image by alt text, or an element by title.

Refining a locator

MethodWhat it doesExample
Importantlocator.locator("button")Search inside an element (chaining).page.locator("#product-3").locator("button")
Importantlocator.first() / last() / nth(2)Pick one of many matches. nth starts at 0.page.locator(".product").nth(1)
Importantlocator.count()How many elements match. Returns an int.page.locator(".product").count()
Good to knowlocator.filter(new Locator.FilterOptions().setHasText("Pen"))Keep only the matches that contain some text.
Good to knowlocator.and(other) / locator.or(other)Combine two locators.
Good to knowlocator.all()Returns a List<Locator> to loop over.for (Locator p : page.locator(".product").all()) { ... }

ImportantTwo things that surprise beginners

  • Strict mode: if page.locator(".product").click() matches 3 elements, Playwright throws an error instead of clicking one by chance. Fix it with a more exact locator, or .first(), or .nth(i).
  • getByLabel("Password") also matches "Confirm password", because text matching is partial. Use new Page.GetByLabelOptions().setExact(true) to match exactly.
  • Test locators quickly with npx playwright codegen or the Inspector (see debugging).

6. Assertions: checking results

Import this once: import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;. Then write assertThat(locator).hasText("Hello");. These assertions retry for up to 5 seconds until they become true. That is why Playwright tests are stable.

MethodWhat it doesExample
ImportantassertThat(locator).isVisible() / isHidden()Element is shown / not shown.
ImportantassertThat(locator).isEnabled() / isDisabled()Element is clickable / disabled.
ImportantassertThat(locator).isChecked()Checkbox or radio is ticked.
ImportantassertThat(locator).hasText("exact text")The WHOLE text equals this (spaces are ignored). Pass a String[] to check a list of elements, or a Pattern for a regular expression.assertThat(page.locator("#msg")).hasText("Saved");
ImportantassertThat(locator).containsText("part")The text contains this part.
ImportantassertThat(locator).hasValue("abc")An input contains this value.
ImportantassertThat(locator).hasAttribute("type", "password")An attribute has this value.
ImportantassertThat(locator).hasCount(3)Exactly this many elements match.
ImportantassertThat(page).hasURL(...) / hasTitle(...)Check the address or title. Accepts a String or a Pattern.
ImportantassertThat(locator).not().isChecked().not() reverses any check.
Good to knowassertThat(locator).isEmpty() / isEditable() / isFocused()Other state checks.
Good to knowassertThat(locator).hasClass("active") / hasId / hasCSSClass, id or style checks.
Good to knowsetDefaultAssertionTimeout(ms)Change the 5 second default for all assertions.PlaywrightAssertions.setDefaultAssertionTimeout(10000);

ImportantWhich assert to use

  • Use assertThat(locator)... for anything on the page. It waits and retries.
  • Use TestNG Assert.assertEquals(actual, expected) for plain Java values, such as a number you calculated.
  • hasText("") with an empty string checks that the element is empty. It does not mean "anything".

7. Auto-waiting (the big difference from Selenium)

ImportantWhat happens before every click

Before every action, Playwright waits until the element passes these checks. If they do not pass within 30 seconds, you get a TimeoutError.

ActionPlaywright waits until the element is
click(), hover(), check()attached to the page, visible, stable (not moving), enabled, and not covered by another element
fill(), clear()visible, enabled and editable
selectOption()visible and enabled
innerText(), getAttribute()attached to the page

In Selenium you write WebDriverWait and ExpectedConditions yourself. In Playwright this is built in. You only need explicit waiting for special cases, such as locator.waitFor() or page.waitForResponse(...).

page.setDefaultTimeout(10000);                                       // actions wait up to 10 s
page.locator("#late").click(new Locator.ClickOptions().setTimeout(3000));   // this one waits 3 s
page.locator("#spinner").waitFor(new Locator.WaitForOptions()
        .setState(WaitForSelectorState.HIDDEN));                          // wait for the spinner to go

What it does: Changing the default wait time, one custom wait, and waiting for an element to disappear.

8. Popups, frames, tabs, downloads

ImportantAlert, confirm, prompt

Popups: by default Playwright closes (dismisses) alert, confirm and prompt popups by itself. To read one or press OK, register the handler BEFORE the click that opens it.

page.onceDialog(dialog -> {
    System.out.println(dialog.message());   // read the popup text
    dialog.accept();                        // press OK  (dialog.dismiss() = Cancel)
});
page.locator("#submitBtn").click();         // this click opens the popup

What it does: onceDialog handles the next popup only. onDialog handles every popup. A handler that neither accepts nor dismisses blocks the page.

page.frameLocator("#payFrame").getByLabel("Card number").fill("4111111111111111");

What it does: Frames: frameLocator goes into an iframe. No switching back is needed afterwards, unlike Selenium.

Page newTab = page.waitForPopup(() -> page.getByText("Open help").click());
newTab.waitForLoadState();
System.out.println(newTab.title());

What it does: New tab: waitForPopup runs the click and gives you the new tab as another Page object.

Download download = page.waitForDownload(() -> page.getByText("Export").click());
download.saveAs(Paths.get("report.csv"));

What it does: Download: waits for the file and saves it.

page.route("**/api/users", route -> route.fulfill(
        new Route.FulfillOptions().setStatus(200).setBody("[]")));

What it does: Network: replaces the answer of a request with your own. Useful to test an empty list or an error.

APIRequestContext request = playwright.request().newContext();
APIResponse response = request.get("https://reqres.in/api/users/2");
System.out.println(response.status());      // 200
System.out.println(response.text());

What it does: Playwright can also call APIs directly, without a browser, for API tests or test data setup.

9. Setup and cleanup with TestNG

Playwright only drives the browser. We use TestNG (as with Selenium) to run the tests, give annotations and Assert. The annotations @Test, @BeforeMethod, @AfterMethod, @DataProvider work exactly the same. Here is the base class used in the three cases below.

package playwrighttests;​import com.microsoft.playwright.Browser;import com.microsoft.playwright.BrowserContext;import com.microsoft.playwright.BrowserType;import com.microsoft.playwright.Page;import com.microsoft.playwright.Playwright;import org.testng.annotations.AfterClass;import org.testng.annotations.AfterMethod;import org.testng.annotations.BeforeClass;import org.testng.annotations.BeforeMethod;​public class BaseTest {​    protected Playwright playwright;      // the main object: it starts everything    protected Browser browser;            // one browser (Chrome), shared by all tests in a class    protected BrowserContext context;     // a fresh "profile" for each test (like an incognito window)    protected Page page;                  // one tab inside the context​    @BeforeClass    public void launchBrowser() {        playwright = Playwright.create();        browser = playwright.chromium().launch(new BrowserType.LaunchOptions()                .setChannel("chrome")                              // use the Chrome installed on the machine                .setHeadless(Boolean.getBoolean("headless")));     // false = you can watch the browser    }​    @BeforeMethod    public void createPage() {        context = browser.newContext();       // new context = clean cookies, storage, no leftovers        page = context.newPage();    }​    @AfterMethod(alwaysRun = true)    public void closeContext() {        context.close();    }​    @AfterClass(alwaysRun = true)    public void closeBrowser() {        browser.close();        playwright.close();    }}

13. Quick interview answers

  • Important What is Playwright?
    An open-source library from Microsoft to automate Chromium, Firefox and WebKit. It supports Java, JavaScript / TypeScript, Python and C#.
  • Important Explain Playwright, Browser, BrowserContext and Page.
    Playwright starts everything. Browser is the browser program. BrowserContext is an isolated profile like an incognito window. Page is one tab.
  • Important Why is Playwright less flaky than Selenium?
    Auto-waiting before each action, and web-first assertions that retry until true.
  • Important What is auto-waiting?
    Before an action, Playwright waits until the element is attached, visible, stable, enabled and not covered.
  • Important What is a Locator? Why is it better than a WebElement?
    A Locator is a recipe to find an element, and it searches again on every use, so it never goes stale.
  • Important Which locators do you prefer?
    getByRole, getByLabel, getByText, getByTestId first, because they match what users see. CSS and XPath when needed.
  • Important What is strict mode?
    If a locator matches more than one element, an action throws an error instead of picking one. Fix with a better locator, first(), or nth().
  • Important fill() vs pressSequentially()?
    fill() sets the whole value at once. pressSequentially() types key by key like a user, and respects maxlength.
  • Important How do you handle alerts?
    Register page.onceDialog(...) BEFORE the action. Without a handler, Playwright dismisses dialogs automatically.
  • Important How do you handle frames and new tabs?
    page.frameLocator("#id") for frames. page.waitForPopup(() -> click) for a new tab.
  • Important Why a new BrowserContext per test?
    Clean cookies and storage for every test, so tests are independent. Creating a context is very fast.
  • Important Selenium vs Playwright?
    See the table above: auto-wait, retrying assertions, speed, built-in trace and video, contexts.
  • Good to know How do you debug a failing test?
    Run headed with slowMo, use page.pause() and the Inspector, and open the trace viewer for failures in CI.
  • Good to know How do you test the same code on many browsers?
    Change chromium() to firefox() or webkit(), or loop over the three.
  • Good to know How do you reuse a login?
    Log in once, save context.storageState(...) to a file, and start other contexts from that file.
  • Good to know How do you mock an API response?
    page.route("**/api/users", route -> route.fulfill(...)).
  • Good to know Can Playwright test APIs?
    Yes, with playwright.request().newContext() you can send GET, POST and so on, and check response.status().
  • Good to know Does Playwright support parallel tests?
    Yes. With TestNG you can run classes in parallel, and because each test uses its own context they do not disturb each other.

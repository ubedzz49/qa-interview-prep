Selenium with Java: From Zero to Real Tests

You already know Java. This guide teaches only what is new: Selenium words, objects and methods, and how to use them to test a real web page. Every code example is Java and was run successfully.

Important

Red boxes and rows: learn these first. They are used in almost every test and asked in almost every interview.

Good to know

Blue boxes and rows: useful, but you can learn them later or only when needed.

1. What is Selenium and how does it work?

Selenium is a Java library (a set of classes in a jar file) that controls a real browser. Your Java code says "open this page", "type here", "click that button", and the browser does it. Then your code checks the result.

Your Java test→Selenium library→Browser driver (chromedriver)→Chrome browser

Selenium cannot talk to Chrome directly. A small program called the browser driver sits in the middle and translates the commands. In Selenium 4, a helper called Selenium Manager downloads the correct driver for you automatically.

Words you will hear

WordSimple meaning
WebDriverThe main Java interface. One WebDriver object = one browser you can control.
Driver / ChromeDriverWebDriver is the interface. ChromeDriver is the class that opens Chrome. FirefoxDriver and EdgeDriver do the same for other browsers.
WebElementOne thing on the page: a button, text box, link, label. Your code holds it in a WebElement variable.

2. Setup in Java (Maven)

ImportantDependencies

Create a Maven project, then add these dependencies to pom.xml. Maven downloads the jars for you.

<dependency>
  <groupId>org.seleniumhq.selenium</groupId>
  <artifactId>selenium-java</artifactId>
  <version>4.27.0</version>
</dependency>
<dependency>
  <groupId>org.testng</groupId>
  <artifactId>testng</artifactId>
  <version>7.10.2</version>
</dependency>

What it does: selenium-java is Selenium itself. testng is the test framework that runs your tests and gives you Assert. Use a recent Selenium version if you see a newer one on Maven Central. A "CDP version" warning in the console is harmless.

Also install Google Chrome. Nothing else is needed, Selenium Manager gets the driver.

Your first test (complete)

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

public class FirstTest {
    public static void main(String[] args) {
        WebDriver driver = new ChromeDriver();                 // 1. open Chrome
        driver.get("https://example.com");                      // 2. go to a page
        String title = driver.getTitle();                       // 3. read the page title
        System.out.println(title);
        driver.findElement(By.tagName("a")).click();            // 4. find a link and click it
        driver.quit();                                          // 5. close the browser
    }
}

What it does: Five steps that every Selenium test has: open the browser, go to a page, find elements and act on them, check something, close the browser.

ImportantWhy WebDriver on the left side?

WebDriver driver = new ChromeDriver(); The variable type is the interface WebDriver, the object is ChromeDriver. This is Java polymorphism. To run on Firefox you only change the right side to new FirefoxDriver(). Everything else stays the same.

ImportantNever forget quit()

Always call driver.quit(). If you forget it, browser windows stay open and eat memory. In a test class, put it in @AfterMethod so it runs even when the test fails.

5. Locators: how to find an element

A web page is HTML. Each element has attributes like id, name, class. To click a button, you first find it with a locator from the By class.

<input id="email" name="email" type="email" class="form-control" placeholder="you@example.com">
<button type="submit" class="btn">Login</button>

What it does: Example HTML we will find elements in.

MethodWhat it doesExample
ImportantBy.id("email")Finds by the id attribute. Fastest and best when the id is unique and stable.driver.findElement(By.id("email"))
ImportantBy.cssSelector("input#email")Finds with a CSS selector. Fast and flexible.By.cssSelector("button[type='submit']")
ImportantBy.xpath("//button[text()='Login']")Finds with XPath. Most powerful: can use text and parent / child.By.xpath("//input[@id='email']")
ImportantBy.name("email")Finds by the name attribute.By.name("email")
ImportantBy.linkText("Forgot password?")Finds a link by its full visible text.By.linkText("Sign up")
Good to knowBy.partialLinkText("Forgot")Link text that contains the given part.
Good to knowBy.className("btn")Finds by one class name. Many elements often share a class.By.className("btn")
Good to knowBy.tagName("a")Finds by tag. Used to get lists like all links or all rows.driver.findElements(By.tagName("a"))
Good to knowRelativeLocator.with(By.tagName("input")).below(By.id("email"))Selenium 4: find by position (above, below, toLeftOf, toRightOf, near).

CSS and XPath cheat sheet

Want to findCSS selectorXPath
By id#email//*[@id='email']
By class.btn//*[@class='btn']
Tag with attributeinput[type='email']//input[@type='email']

ImportantLocator rules

  • Order of choice: id first, then CSS, then XPath.
  • XPath that starts with // is relative and safe. XPath like /html/body/div[2]/div[1]/button is absolute and breaks when the page changes a little.
  • Get a locator: right click the element in Chrome, click Inspect, read its attributes. Test your locator in the Console: $x("//button[text()='Login']") for XPath and $$("#email") for CSS.
  • If an id changes on every load (like btn_8374), use starts-with() or contains().

Dropdown: the Select class

Works only for the HTML <select> tag. Wrap the element in Select.

Select country = new Select(driver.findElement(By.id("country")));

String chosen = country.getFirstSelectedOption().getText();

Popups: the Alert interface

Alert alert = wait.until(ExpectedConditions.alertIsPresent());   // wait for the popup
String text = alert.getText();     // read the message
alert.accept();                    // press OK
// alert.dismiss();                // press Cancel
// alert.sendKeys("abc");          // type into a prompt box

What it does: Waits for a popup, reads it, and presses OK.

ImportantAlert rule

While a popup is open, Selenium cannot do anything else on the page. You will get UnhandledAlertException. Always handle the popup first.

Mouse and keyboard: the Actions class

Actions actions = new Actions(driver);
actions.moveToElement(menu).perform();                 // hover
actions.doubleClick(button).perform();                 // double click
actions.contextClick(item).perform();                  // right click
actions.dragAndDrop(source, target).perform();         // drag and drop
actions.sendKeys(Keys.ESCAPE).perform();               // press a key

What it does: Every Actions chain must end with perform(), or nothing happens.

Special keys

box.sendKeys("selenium", Keys.ENTER);                   // type and press Enter
box.sendKeys(Keys.BACK_SPACE);                          // delete one character
box.sendKeys(Keys.chord(Keys.CONTROL, "a"));            // Ctrl + A (use Keys.COMMAND on Mac)

What it does: Keys has ENTER, TAB, ESCAPE, BACK_SPACE, ARROW_UP, ARROW_DOWN and more.

JavascriptExecutor

JavascriptExecutor js = (JavascriptExecutor) driver;
js.executeScript("arguments[0].scrollIntoView(true);", element);      // scroll to element
js.executeScript("arguments[0].click();", element);                   // click with JavaScript
js.executeScript("arguments[0].value = arguments[1];", dateBox, "2000-05-20");   // set a value
Object title = js.executeScript("return document.title;");

What it does: Runs JavaScript inside the page. arguments[0] is the first value you pass after the script text.

Use it when normal Selenium cannot do the job: date pickers, hidden elements, scrolling, or a click that is blocked by another element. Try normal Selenium first.

Frames, windows and file upload

8. Waits: the most important topic

ImportantWhy we need waits

A page needs time to load. If your code looks for a button before it appears, you get NoSuchElementException. A wait tells Selenium to give the page a little time. Without waits, tests fail randomly.

WaitHow it worksAdvice
ImplicitOne global rule: for every findElement, keep trying up to N seconds.Simple, but do not mix with explicit waits.
Explicit (WebDriverWait)Wait for ONE condition on ONE element (visible, clickable...).Best choice. Use this.
FluentExplicit wait where you also set how often to check and which errors to ignore.For special cases.
Thread.sleepStops for a fixed time.Avoid. It always waits the full time.
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(5));

What it does: Implicit wait: for the whole test, find calls retry for up to 5 seconds.

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
WebElement msg = wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("msg")));
wait.until(ExpectedConditions.elementToBeClickable(By.id("payBtn"))).click();

What it does: Waits up to 10 seconds, but continues the moment the condition is true. If it never becomes true, a TimeoutException is thrown.

MethodWhat it doesExample
ImportantvisibilityOfElementLocated(By)Element is in the page and visible. Returns the element.
ImportantelementToBeClickable(By)Element is visible and enabled, ready to click.
ImportantpresenceOfElementLocated(By)Element exists in the HTML (it may still be hidden).
ImportantalertIsPresent()A popup is open.
Good to knowinvisibilityOfElementLocated(By)Element has gone (for example a loading spinner).
Good to knowtextToBePresentInElementLocated(By, text)Element contains the given text.
Good to knowtitleContains(text) / urlContains(text)Page title or URL has the text.
Good to knowframeToBeAvailableAndSwitchToIt(...)Frame is ready and Selenium switches into it.
Good to knownumberOfElementsToBe(By, n)Exactly n elements found.
Good to knowstalenessOf(element)The old element is gone from the page.
Wait<WebDriver> fluent = new FluentWait<>(driver)
        .withTimeout(Duration.ofSeconds(20))
        .pollingEvery(Duration.ofMillis(500))
        .ignoring(NoSuchElementException.class);
WebElement el = fluent.until(d -> d.findElement(By.id("late")));

What it does: Fluent wait: check every 500 ms for up to 20 seconds, and ignore "not found" errors while waiting.

11. Page Object Model (design pattern)

Good to knowPOM

Without POM, every test has locators inside it. If a locator changes, you edit many tests. In POM each page gets one class holding its locators and actions. Tests only call these actions. The three cases below keep things simple, so the locators and helper methods sit inside each test class. A real project would move them into page classes like this:

public class LoginPage {
    private final WebDriver driver;
    private final By email = By.id("email");
    private final By password = By.id("pass");
    private final By loginBtn = By.id("loginBtn");

    public LoginPage(WebDriver driver) { this.driver = driver; }

    public void loginAs(String user, String pass) {
        driver.findElement(email).sendKeys(user);
        driver.findElement(password).sendKeys(pass);
        driver.findElement(loginBtn).click();
    }
}
// in a test:  new LoginPage(driver).loginAs("qa@test.com", "Test@1234");

What it does: Locators are private and hidden (encapsulation). If the id changes, you fix one line.

13. Quick interview answers

  • Important What is Selenium?
    An open-source library to automate web browsers. It supports many languages (Java, Python, C#) and browsers (Chrome, Firefox, Edge, Safari). It does not test desktop or mobile apps (mobile uses Appium).
  • Important Why WebDriver driver = new ChromeDriver() and not ChromeDriver driver = ...?
    WebDriver is an interface. Writing the interface on the left lets you switch to another browser by changing one word on the right.
  • Important findElement vs findElements?
    One element and an exception if none, versus a list that is empty if none.
  • Important close() vs quit()?
    close() closes the current window. quit() closes all windows and ends the session.
  • Important Implicit vs explicit wait?
    Implicit: global, for all elements. Explicit: one condition for one element, with WebDriverWait. Prefer explicit, and never mix the two.
  • Important Which locator do you prefer?
    id first, then CSS, then relative XPath, because they are fast and stable.
  • Important XPath vs CSS?
    XPath can search by text and move to parent elements. CSS is simpler and usually faster.
  • Important Absolute vs relative XPath?
    Absolute starts from the root (/html/...) and breaks easily. Relative starts with // and is safer.
  • Important How do you handle a dropdown, an alert, a frame, a new window?
    Select class; switchTo().alert(); switchTo().frame(); getWindowHandles() + switchTo().window().
  • Important How do you handle StaleElementReferenceException?
    The page changed and the saved element is old. Find the element again.
  • Important What is Page Object Model?
    A design pattern: one class per page that holds its locators and actions. It reduces repeated code and makes maintenance easy.
  • Important How does TestNG help?
    Runs tests, gives annotations (@Test, @BeforeMethod), assertions, data providers, grouping, parallel runs and reports.
  • Good to know What is a data provider?
    A method that returns rows of data. The test method runs once per row.
  • Good to know How do you upload a file?
    sendKeys with the file path on the <input type="file">. Do not click it.
  • Good to know How do you run tests without a visible browser?
    Headless mode with ChromeOptions.addArguments("--headless=new").
  • Good to know What is Selenium Grid?
    Runs tests in parallel on many browsers and machines.
  • Good to know What are Selenium limitations?
    Web only, no built-in reports, needs explicit waits, and cannot handle captcha or image checks.
  • Good to know Selenium vs Playwright?
    Playwright has built-in auto-waiting, is often faster, and has built-in tracing. Selenium has the bigger community and more language support. Learn both ideas.
